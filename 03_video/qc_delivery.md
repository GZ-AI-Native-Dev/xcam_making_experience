## 三帧 QC 法

每条候选抽三帧：**约 0.5s / 中段 / 尾段（约 7.5s）**，逐项对比：

- 人物大小是否一致（推近拉远检测）
- 头部位置、手位是否一致
- 背景地标位置是否一致
- gift：特效是否在尾帧前完全消散
- idle / action：是否保持静默（action 骚版只有非人声音景）
- gift 口播：是否只有那一句短中文
- typing：是否只有预期的键盘/触屏声、无人声
- 首尾是否回到 Picture 2 姿态

## 坏例记录目录

坏视频有学习价值才保留：`rejected/videos/` + 同名 `rejected/prompts/`，notes 写明可见失败类型：

- 推近 / 拉远 / 变焦
- 人物比例变化
- 脸或身体被裁
- 意外说话
- 意外字幕或 UI
- 礼物变成实体物品
- 动作变多镜头/多步骤
- preview 变露骨、写真感、特写、角色间雷同
- typing 出现可见键盘/手机（应画面外）
- typing 变对白、字幕、聊天 UI、平台界面
- 人物走太近导致裁切，或镜头变焦代替人物移动

## 角色交接交付物清单

每个角色交接时必须交付：

| 阶段 | 必须交付 | 检查方法 |
| --- | --- | --- |
| 首帧 | 首帧图 + 首帧提示词 + 使用的明星 LoRA 或 edit 模型 | 9:16、直视镜头、平视、背景清楚、人物场景匹配 |
| 视频提示词 | idle / gift / action / typing 中英文提示词 | MiniMax 三段结构、首尾帧对齐、固定镜头 |
| 视频候选 | 每个动作 1-3 个候选视频 | 抽开头/中间/结尾三帧，看推近拉远、是否回尾帧 |
| 人工筛选 | 合格候选 + 不合格候选 + 坏例原因 | 记录推近拉远/字幕/说话/动作过快/人物变形/礼物挡脸 |
| 上线资料 | 角色名、年龄、职业、描述、选中视频地址 | 描述统一中文；角色定位写清（安静治愈型/甜美互动型等） |

上线资料字段可参照角色预览站（`demo.xshow.live/interactive`）的角色卡片。
